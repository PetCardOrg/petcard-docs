## Resumo Executivo

- **9 dos 12 achados de 01/06 estão resolvidos e verificados no código** — incluindo os dois 🔴 de segurança/escopo: tokens OAuth agora cifrados (AES-256-GCM, `EncryptionService` + `ENCRYPTION_KEY` no `.env.example`) e RF12 (export PDF) implementado (`expo-print`, `src/utils/generateWalletPdf.ts`, PC-110 mergeada).
- **M6 avançou muito, mas não fechou.** PC-086/087/088 (api) e PC-089 (web) entregues e verificadas: API com 43 specs unit + 5 e2e, threshold restaurado em **81/74/87/83** e CI verde com Postgres/PostGIS real; web com 14 arquivos de teste e thresholds 80/75/78/80 no Vitest. **Restam: PC-090 (mobile: 0 testes, 0 infra), PC-091, PC-094, PC-095.**
- **🔴 Novo P0: `npm audit` acusa 50 vulnerabilidades no ecossistema** — 1 **crítica** no mobile (`shell-quote`), 10 high na api (cadeia `@nestjs/*`/`multer`/`form-data`), 3 high no web (`react-router`, `vite`) — a maioria com fix disponível via bump. É exatamente o escopo da PC-095, que está aberta.
- **🔴 `main` voltou a ficar atrás de `develop` em todos os repos** (6–8 commits): todo o trabalho de junho (testes de M6, PDF, ADR-004) existe só em `develop`. Diferente de 01/06, **não há divergência bidirecional real** — os commits "só em `main`" são apenas merge commits de PRs `develop→main` anteriores. Um novo merge resolve.
- **🟡 TAP, DAS e as auditorias não estão versionados** — vivem apenas na pasta local `tcc/docs/`, que não é repositório git. Uma falha de disco perde os documentos centrais do TCC. O lugar natural é `petcard-docs`.

## Backlog Priorizado

### P0 — Bloqueante / Segurança

- [x] **[M6] Corrigir vulnerabilidades npm (PC-095)**
  - Repositório/arquivo: todos — `package-lock.json`
  - Problema: 50 vulns no total. **mobile: 1 crítica** (`shell-quote` — RCE-adjacente via escape de newline; runtime na árvore do lockfile, embora chegue via tooling RN/Metro que não entra no bundle do app) + `form-data` (CRLF), `undici`, `ws` (DoS), todas com fix disponível. **api: 10 high** — `multer` (DoS em upload — rota real de receitas/exames), `form-data`, `@grpc/grpc-js`/`protobufjs` (cadeia do firebase-admin), e a cadeia `@nestjs/*`. **web: 3 high** — `react-router` (CSRF via PUT — runtime!), `vite` (dev-only).
  - Ação recomendada: `npm update` + re-audit em cada repo. **Atenção:** o `npm audit fix --force` da api sugere *downgrade* do NestJS para v7 — ignorar; a api está no Nest 11, o caminho certo é bump de patch/minor dentro do 11.x (que atualiza o `multer` transitivo) e atualização do `firebase-admin`. Fechar PC-095 com o resultado documentado.

- [x] **[Dívida Técnica] Mergear `develop` → `main` em todos os repos**
  - Repositório/arquivo: api (7 commits), web (8), mobile (6), docs (6)
  - Problema: todo o trabalho de junho (PC-086/087/088/089/096/110, ADR-004) está fora do branch oficial — mesma classe do achado nº 1 de 01/06, que a banca pode clonar.
  - Ação recomendada: abrir PRs `develop→main` nos 4 repos. Sem risco bidirecional desta vez (os commits exclusivos de `main` são só merge commits antigos). Considerar automatizar: fazer o merge a cada fechamento de milestone.

### P1 — Alta Prioridade

- [x] **[M6] PC-090 — Testes de componentes no mobile**
  - Repositório/arquivo: `petcard-mobile` (0 arquivos de teste, sem runner)
  - Problema: único repo de produto sem nenhum teste; era o último bloqueador técnico "grande" da M6 e o roteiro (CLAUDE.md da api) já previa fazê-lo por último, com a infra de teste madura.
  - Ação recomendada: bootstrap `jest-expo` + `@testing-library/react-native`; cobrir carteira do pet, scanner e listas de saúde com mocks de navegação/API; adicionar step de teste no `ci.yml` (hoje o CI do mobile **não roda teste nenhum**). DoD: CI verde.

- [x] **[M6] PC-091 — Relatório de cobertura no CI de cada repo**
  - Repositório/arquivo: `.github/workflows/ci.yml` de api, web, mobile, shared
  - Problema: api e web **rodam** `test:cov` no CI, mas nenhum workflow publica o relatório (sem `upload-artifact`, sem Codecov, sem badge); mobile e shared não rodam testes.
  - Ação recomendada: upload do `lcov` como artifact (ou Codecov) em api/web; incluir mobile após PC-090; para o shared, decidir explicitamente "sem testes por ser pacote de tipos" e fechar a issue com essa justificativa.

- [x] **[Dívida Técnica] Versionar TAP, DAS e auditorias**
  - Repositório/arquivo: `tcc/docs/{TAP.md,DAS.md,Auditoria-*.md}` — pasta local **fora de git**
  - Problema: os três documentos centrais do TCC (incluindo o DAS atualizado no Dia 4, trabalho real) não têm backup nem histórico; o `petcard-docs` só versiona ADRs/README/CONTRIBUTING.
  - Ação recomendada: mover (ou copiar mantendo fonte única) para `petcard-docs/` — ex.: `docs/tap.md`, `docs/das.md`, `docs/auditorias/`.

### P3 — Baixa Prioridade / Nice-to-have

- [ ] **[Dívida Técnica] Decorators Swagger nos controllers (parte da PC-097, M7)**
  - Repositório/arquivo: 15 controllers em `petcard-api/src/modules/*/`
  - Problema: `SwaggerModule` + plugin CLI já geram schemas dos DTOs, mas sem `@ApiTags`/`@ApiOperation`/`@ApiBearerAuth` o `/docs` fica sem agrupamento nem descrição — perde o efeito "impressionar a banca".
  - Ação recomendada: `@ApiTags` por controller e `@ApiBearerAuth` nas rotas com `@Auth()`; `@ApiOperation` ao menos nas rotas públicas (`GET /cards/:token`).

- [ ] **[Dívida Técnica] Redis provisionado e nunca usado**
  - Repositório/arquivo: `petcard-api/docker/docker-compose.yml` (serviço `redis`), `.env.example` (`REDIS_*`)
  - Problema: sobe um container que nenhuma linha de código consome. Já **documentado honestamente no DAS** ("capacidade reservada"), então não é inconsistência — é custo de setup.
  - Ação recomendada: manter só se a narrativa de "reserva" for usada na defesa; caso contrário, remover do compose e do `.env.example` (par com a exclusão abaixo).
